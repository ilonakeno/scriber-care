# Scriber Care

**AI-асистент для команди підтримки, який закриває звернення дією, а не відповіддю.**
Він розуміє, чого клієнт хоче насправді і в якому він стані, сам підтягує контекст і виконує
потрібну дію в межах автономності, яку задає керівник підтримки. Щодня він також розбирає
відгуки на G2 і Capterra, перетворює скарги на вирішені звернення і звітує команді в Slack.

Демо-продукт: **Scriber**, AI-скрайбер для протоколів УЗД (лікар диктує → розпізнавання →
структурований протокол → експорт). Хакатон PolyTech Code Fest 2026, трек Skelar
«AI Customer Support Automation».

> Усі лікарі, клініки, пацієнти, звернення, відгуки й конкуренти в репозиторії **вигадані**.
> Бекенд Scriber симульований. Цифри на дашборді рахуються з цих синтетичних даних.

## Проблема

Підтримка коштує компанії грошей двічі: агенти витрачають час на уточнення і ручні дії, а клієнти
з невирішеною проблемою йдуть. Найрозчарованіші взагалі не пишуть у підтримку, а ставлять низьку
оцінку на майданчику відгуків, де їх ніхто не обробляє.

## Що вміє

| Вимога брифу | Як це зроблено |
|---|---|
| Зрозуміти справжню мету | «Скасуйте підписку» насправді означає «виправте розпізнавання терміна»: AI бачить у контексті три однакові правки |
| Запропонувати або запустити дію | Словник, перегенерація протоколу, відновлення запису, кредит, місця, баг-тікет, відповідь на відгук |
| Допомогти агенту вирішити | Заявлено проти справжньої мети, вердикт, тон, сарказм, ризик відтоку, докази, правило для кожної дії |
| Аналізувати та оцінювати | % вирішено AI / підтримкою / розробниками, час, звернення без уточнень, відгуки, конкуренти |

**Пріоритети й автономність.** P3 рутина: AI робить сам. P2 гроші, підписка, публічні відповіді:
тільки з підтвердженням. P1 масова проблема: баг-тікет у GitHub + Slack розробникам. P0 клінічний
ризик, дані пацієнта, погрози, спроба керувати асистентом або низька впевненість: AI не робить
нічого, кейс у людини. Керівниця підтримки може послабити ліміти повзунком (наприклад, кредит
до $35 при впевненості ≥ 90%).

## Архітектура

```
Чат лікаря                 Відгуки G2 / Capterra (щоденний прохід)
      └──────────┬──────────────┘
                 ▼
   Маскування персональних і медичних даних (app/masking.py)
                 ▼
   Контекст: акаунт · правки термінів · база знань фіч (docs/) · плейбук
                 ▼
   Gemma 4 через Gemini API → JSON: мета, вердикт, тон, план (app/ai.py)
                 ▼
   Рушій правил: дозволений список, ліміти, P0–P3 (app/policy.py)
     ├─ P3 → виконати (app/actions.py) → відповідь клієнту
     ├─ P2 → Slack #support «Підтвердити» → агент
     ├─ P1 → GitHub Issue + Slack #dev, тегає власника фічі
     └─ P0 → тільки людина
                 ▼
   Журнал з хеш-ланцюжком (app/audit.py) → метрики → дашборд і звіт у Slack
```

**Модель лише пропонує, виконує код.** Ризики (дані пацієнта, клінічний ризик, погрози,
prompt injection) визначаються детерміновано, тож модель може підняти кейс до P0, але не може
опустити. Якщо API недоступний, працює прозорий запасний аналізатор на правилах, і кожен кейс
показує, який двигун його обробив.

**База знань по фічах** (`docs/features/<фіча>/`): `FEATURE.md` (що, бізнес-правила, власник,
точки входу), `e2e-flow.md`, `known-gotchas.md`. Вердикт «не баг» AI ставить лише коли симптом
описаний у базі. Коли агент вирішує новий випадок, система пропонує доповнити базу.

## Безпека

- Маскування імен пацієнтів, телефонів, email, дат народження, номерів карт до виклику моделі.
- Дозволений список дій і жорсткі ліміти (кредит не більший за місячну оплату, списання не більше
  фактичної переплати, 1–20 місць). Видалення даних пацієнта для AI не існує.
- Звернення й відгуки вважаються недовіреними даними; спроба керувати асистентом веде в P0.
- У Slack і в публічні відповіді нічого не йде без фільтра персональних даних; публічні відповіді
  завжди підтверджує людина.
- Журнал дій з хеш-ланцюжком: правку заднім числом видно одразу.
- Секрети тільки в `.env` (у `.gitignore`).
- Для проду: Gemma — відкрита модель, її можна запустити у власній інфраструктурі, щоб медичні
  дані не залишали периметр. Безкоштовний Gemini API тут використано лише тому, що дані синтетичні.

## Запуск

```bash
python3.14 -m venv .venv
.venv/bin/pip install fastapi uvicorn google-genai httpx pytest
cp .env.example .env   # GEMINI_API_KEY, за бажанням Slack-вебхуки і GITHUB_REPO
.venv/bin/uvicorn app.main:app --port 8000
```

- `http://localhost:8000/` — панель агента
- `http://localhost:8000/chat` — чат лікаря
- `http://localhost:8000/dashboard` — дашборд, повзунок автономності, прохід по відгуках, звіт

## Тести і якість AI

```bash
.venv/bin/python -m pytest -q        # правила, маскування, журнал, prompt injection
.venv/bin/python -m eval.run_eval    # еталонний набір звернень
```

Тест-кейси правил написані зі специфікації **до** реалізації (див. історію комітів).
`eval/golden.json` містить звернення з очікуваним пріоритетом, вердиктом і діями; розмітку
перевіряє людина до налаштування промпту, а скрипт рахує, скільки AI вгадав.
