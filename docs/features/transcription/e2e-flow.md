# Розпізнавання мовлення: наскрізний потік

1. Лікар відкриває Scriber за HTTPS-адресою в Chrome, Safari або на iPhone.
2. Браузер просить дозвіл на мікрофон для сайту. Без дозволу (або без HTTPS) запис не стартує.
3. Лікар натискає запис. `MediaRecorder` пише аудіо сегментами по ~8 с у стисненому форматі з низьким бітрейтом.
4. Щойно сегмент готовий, браузер надсилає його на `POST /api/transcribe`. Довгий запис не вантажиться одним файлом, тому великих аплоадів і відмов через розмір нема.
5. Сервер передає сегмент у Whisper з українською мовою й підказкою: загальний словник УЗД-термінів плюс особистий словник цього лікаря.
6. Whisper повертає текст сегмента, фронтенд дописує його блоком у живий текст. Зазвичай це 1-2 секунди після завершення сегмента.
7. На екрані секундомір показує час запису і час розпізнавання.
8. Лікар зупиняє запис: останній сегмент закривається й розпізнається, решта вже готова, тож фіналізація майже миттєва.
9. Збій по дорозі (обрив мережі, блокування екрана): уже розпізнані сегменти лишаються, сегмент «у польоті» губиться. `restore_recording` збирає текст із розпізнаних сегментів.
10. Лікар читає текст і виправляє слова. Правки термінів («було → стало») фіксуються знеособлено.
11. Новий термін в особистому словнику (`add_term_personal_dictionary`) діє для наступних диктовок цього лікаря. Для вже готового протоколу є `regenerate_protocol`.
12. Розпізнаний текст передається в генерацію протоколу: `docs/features/protocol-generation/`.
